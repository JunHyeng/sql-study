# 3강: NULL 다루기

## 오늘의 목표

- NULL이 "0"이나 "빈칸 글자"와 어떻게 다른지 설명할 수 있다.
- `IS NULL` / `IS NOT NULL`로 값이 없는 행을 찾을 수 있다.
- `IFNULL`, `COALESCE`로 NULL을 다른 값으로 바꿔 보여 줄 수 있다.

## 1. NULL은 "값이 없음(모름)"이다

`customers` 테이블을 조회해 보면 `phone` 열에 `[NULL]`이라고 표시된 칸이 있습니다.

```sql
SELECT name, phone FROM customers;
```

| 값 | 뜻 | 예시 |
|---|---|---|
| `0` | 숫자 0이라는 **값이 있음** | 재고 0개 |
| `''` (빈 글자) | 글자 수 0인 **값이 있음** | 연락처 칸을 일부러 비워 저장 |
| `NULL` | **값 자체가 없음 / 모름** | 연락처를 아예 입력하지 않음 |

엑셀로 치면 0이 들어 있는 칸과 아무것도 입력하지 않은 칸의 차이입니다. 실무 데이터에는 NULL이 정말 많습니다. 회원가입 때 선택 항목을 안 쓴 고객, 비회원 주문, 아직 퇴사하지 않은 직원의 퇴사일 같은 것들입니다.

## 2. NULL은 `=`로 찾을 수 없다 (가장 중요)

```sql
-- ❌ 오류는 안 나지만 결과가 0행
SELECT name FROM customers WHERE phone = NULL;

-- ✅ 올바른 방법
SELECT name FROM customers WHERE phone IS NULL;
```

이유: NULL은 "모르는 값"이라 **어떤 것과 비교해도 결과가 참도 거짓도 아닌 "모름(UNKNOWN)"**이 됩니다. `NULL = NULL`조차 "모름"입니다. 모르는 값 둘이 같은지 알 수 없기 때문입니다. WHERE는 **참인 행만** 남기므로 아무것도 안 나옵니다.

> [!WARNING]
> `= NULL`은 오류 없이 0행을 돌려줍니다. 2강 8번처럼 **조용히 틀리는** 유형이라 실무에서 특히 위험합니다. NULL을 찾을 때는 무조건 `IS NULL`.

### 예제 1: 연락처가 있는 고객만

```sql
SELECT name, phone
FROM customers
WHERE phone IS NOT NULL;
```

### 예제 2: 다른 조건과 함께

```sql
SELECT name, city
FROM customers
WHERE phone IS NULL
  AND city = '경기';
```

결과 2행.

## 3. NULL은 계산을 "오염"시킨다

NULL이 들어간 계산은 결과도 NULL이 됩니다. 모르는 값에 1을 더해도 모르는 값이기 때문입니다.

```sql
SELECT 100 + NULL;                    -- 결과: NULL
SELECT CONCAT('김민수', ' / ', NULL); -- 결과: NULL
```

`CONCAT`은 글자를 이어 붙이는 MySQL 함수입니다. 하나라도 NULL이면 전체가 NULL이 됩니다. 연락처가 없는 고객은 "이름 / 연락처"가 통째로 사라지는 거죠.

## 4. NULL을 다른 값으로 바꾸기: IFNULL, COALESCE

### IFNULL(값, 대신할값): MySQL 전용, 2개만

```sql
SELECT name,
       IFNULL(phone, '미등록') AS 연락처
FROM customers;
```

phone이 NULL이면 `'미등록'`, 아니면 원래 값이 나옵니다.

### COALESCE(값1, 값2, 값3, …): 표준 SQL, 여러 개 가능

```sql
SELECT name,
       COALESCE(phone, '미등록') AS 연락처
FROM customers;
```

왼쪽부터 보면서 **처음으로 NULL이 아닌 값**을 돌려줍니다. 예를 들어 `COALESCE(휴대폰, 집전화, '없음')`이면 휴대폰 → 집전화 순서로 있는 것을 쓰고, 둘 다 없으면 `'없음'`이 됩니다.

> [!TIP]
> `COALESCE`는 MySQL, Oracle, PostgreSQL 어디서나 됩니다. Oracle에는 `IFNULL` 대신 `NVL`이 있습니다. 하나만 익힌다면 **COALESCE**를 추천합니다.

## 5. 실무에서는 이렇게 쓰입니다

- "비회원 주문은 몇 건이에요?" → `WHERE customer_id IS NULL`
- "문자 발송 대상 뽑아 주세요" → `WHERE phone IS NOT NULL` (연락처 없는 사람에게는 못 보내니까)
- 보고서에 빈칸 대신 "미등록", 금액은 0으로 보여 주기 → `COALESCE(phone, '미등록')`, `COALESCE(할인금액, 0)`

엑셀 결산을 할 때 빈칸 때문에 합계나 평균이 이상하게 나온 경험이 있다면, SQL에서 그 역할을 하는 게 NULL입니다. 6강 집계 함수에서 이 문제를 다시 다룹니다.


**문제 2.** 연락처가 **있는** 고객의 이름과 연락처를 조회하세요. (결과 7행)

```sql
select name from customers where phone is not NULL;
```

**문제 3.** 비회원 주문(고객번호가 없는 주문)의 주문번호, 주문일, 결제수단을 조회하세요. (결과 2행)

```sql
select name, coalesce(phone, '미등록') from customers;
```

**문제 5.** 회원 주문(고객번호가 **있는** 주문) 중에서 카드로 결제한 주문의 주문번호를 조회하세요. (결과 9행)

```sql
select order_id from orders where customer_id is not null and payment = '카드';
```

**문제 6. (함정 문제)** 아래 쿼리를 실행해 보고, 결과에서 이상한 점과 그 이유를 적은 뒤 고쳐 주세요.

```sql
SELECT name,
       CONCAT(name, ' / ', phone) AS 고객정보
FROM customers;
```

이상한 점과 이유:
>고객이름은 존재하는데 고객정보에 NULL 값으로 나옴

고친 쿼리 (연락처가 없으면 `이름 / 미등록`으로 나오게):

```sql
SELECT name,

CONCAT(name, ' / ', coalesce(phone, '미등록')) AS 고객정보

FROM customers;
```

## 이해 확인 질문

1. `0`, `''`(빈 글자), `NULL`의 차이를 한 문장씩 설명해 보세요.
	0은 숫자 값이 0이라는 뜻, ''는 글자가 없다는 뜻, NULL은 데이터가 존재 하지 않거나 모른다는 뜻
2. `WHERE phone = NULL`이 오류 없이 0행을 돌려주는 이유는 무엇인가요?
	IS NULL을 사용 안했기 때문에, NULL은 값을 모른다는 뜻이기도 해서 0행을 돌려주는 거다.
3. `COALESCE(NULL, NULL, '세번째', '네번째')`의 결과는 무엇일까요?
	세번째 값, 네번째 값이 NULL일 경우 세번째 값에는 '세번째'로 채우고, 네번째 값에는 '네번째'로 채운다는 뜻

### 피드백 1: COALESCE는 "처음으로 NULL이 아닌 값 하나"를 돌려준다

```sql
COALESCE(NULL, NULL, '세번째', '네번째')   -- 결과: '세번째' (값 1개)
```

- 칸을 하나씩 채우는 함수가 아닙니다. **결과는 항상 값 1개**입니다.
- 왼쪽부터 차례로 보다가 처음 만나는 NULL이 아닌 값을 돌려주고 **거기서 멈춥니다**. 그래서 `'네번째'`는 아예 보지도 않습니다.
- 4번 문제의 `COALESCE(phone, '미등록')`도 같은 원리입니다. phone이 NULL이 아니면 phone에서 멈추고, NULL이면 다음 칸인 `'미등록'`으로 넘어갑니다.

| 식 | 결과 |
|---|---|
| `COALESCE('010-1111', '미등록')` | `'010-1111'` (첫 칸에서 멈춤) |
| `COALESCE(NULL, '미등록')` | `'미등록'` |
| `COALESCE(NULL, NULL, '세번째', '네번째')` | `'세번째'` |
| `COALESCE(NULL, NULL)` | `NULL` (끝까지 NULL이 아닌 값이 없음) |

### 피드백 2: 6번 "이유"까지 적기

현상(고객정보가 NULL로 나옴)은 정확히 찾았습니다. 이유까지 쓰면 이렇습니다.

> 연락처가 NULL인 고객은 `CONCAT`에 NULL이 하나 끼게 되고, **NULL이 들어간 계산은 결과 전체가 NULL**이 되기 때문에 이름까지 통째로 사라진다.

실무에서 "현상"만 보고하면 상대가 원인을 다시 찾아야 합니다. **현상 + 원인 + 해결**을 한 세트로 말하는 습관이 분석가에게 중요합니다.

### 피드백 3: `= NULL`이 0행인 이유

"IS NULL을 안 썼기 때문"은 결과이고, 원인은 이렇습니다.

1. NULL과 비교하면 결과가 참도 거짓도 아닌 **"모름(UNKNOWN)"**이 된다. `NULL = NULL`도 모름.
2. WHERE는 **참인 행만** 남긴다.
3. 모든 행이 "모름"이라 하나도 남지 않는다 → 0행.

### 피드백 4: 요청한 열과 정확히 맞추기 (2강부터 반복)

2강에서는 열을 **더** 넣었고, 이번에는 **빠뜨렸습니다**. 쿼리를 다 쓴 뒤 문제를 다시 읽고 "이름, 연락처" 같은 **열 목록을 손가락으로 하나씩 짚어 보는** 습관을 들여 보세요. 실무에서 요청과 다른 열이 나가면 보고서를 다시 뽑아야 합니다.

### 재확인 (2026-11-21)

- `COALESCE(NULL, '두번째', '세번째')` → 두번째 ✅ / `COALESCE('첫번째', NULL, '세번째')` → 첫번째 ✅
- 휴대폰→집전화→'연락처 없음' 식: `coalease(IFNULL(mobile, 'home_phone'), '연락처 없음')` ❌ → 정답 `COALESCE(mobile, home_phone, '연락처 없음')`
- 연락수단 쿼리: `coalesce(phone, '지역', '정보 없음') as 연락처` ❌ → 정답 `COALESCE(phone, city, '정보 없음') AS 연락수단`
- 판정: **COALESCE 동작은 이해함. 컬럼을 작은따옴표로 감싸는 실수가 반복됨** → 4강 맨 앞 "따옴표 복습"과 복습 문제로 이어서 확인
