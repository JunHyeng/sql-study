# 10강: 테이블 만들기와 1단계 종합 테스트

1단계 마지막 강입니다. 전반부에서 **테이블을 직접 설계**하고, 후반부에서 1~9강 전체를 섞은 **종합 테스트**를 봅니다.

## 오늘의 목표

- `CREATE TABLE`로 테이블을 만들 수 있다.
- 자료형(INT, VARCHAR, DATE …)을 데이터에 맞게 고를 수 있다.
- 제약조건(PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, DEFAULT, CHECK)이 **잘못된 데이터를 막는** 원리를 설명할 수 있다.

## 1. CREATE TABLE 기본

`cafe_schema.sql` 안에 이미 있던 문장입니다. 이제 직접 읽고 쓸 수 있습니다.

```sql
CREATE TABLE 테이블이름 (
    컬럼이름  자료형  제약조건,
    컬럼이름  자료형  제약조건,
    ...
);
```

## 2. 자주 쓰는 자료형 (MySQL)

| 자료형 | 저장하는 것 | 예시 |
|---|---|---|
| `INT` | 정수 | 가격, 수량, 번호 |
| `DECIMAL(전체자리, 소수자리)` | **정확한** 소수 | 금액 `DECIMAL(12, 2)`, 환율 |
| `VARCHAR(n)` | 최대 n글자 가변 문자 | 이름 `VARCHAR(50)` |
| `CHAR(n)` | 항상 n글자 고정 문자 | 성별 `CHAR(1)`, 우편번호 |
| `TEXT` | 긴 글 | 리뷰 내용, 메모 |
| `DATE` | 날짜 | `2025-10-01` |
| `DATETIME` | 날짜 + 시간 | `2025-10-01 14:30:00` |
| `TINYINT(1)` / `BOOLEAN` | 참·거짓 (1/0) | 아이스 여부 |

> [!TIP]
> 고르는 기준: **계산할 숫자**면 INT/DECIMAL, **계산 안 하는 번호**(전화번호, 우편번호)는 VARCHAR입니다. 전화번호 `010-1111-2222`를 INT로 저장하면 앞의 0과 하이픈이 사라집니다. 돈은 소수 오차가 생기는 FLOAT 대신 **DECIMAL**을 씁니다.

## 3. 제약조건: 잘못된 데이터를 DB가 막아 준다

| 제약조건 | 뜻 | 막아 주는 것 |
|---|---|---|
| `PRIMARY KEY` (기본키, PK) | 행을 구분하는 **유일한 번호**. NULL 불가, 중복 불가 | 같은 번호 고객 2명 |
| `FOREIGN KEY` (외래키, FK) | 다른 테이블의 PK를 가리킴 | 없는 고객의 주문 (9강 7번 삭제 거부) |
| `NOT NULL` | 반드시 값이 있어야 함 | 이름 없는 메뉴 |
| `UNIQUE` | 중복 불가 (NULL은 가능) | 같은 이메일로 두 번 가입 |
| `DEFAULT 값` | 안 넣으면 기본값 | 가입일 안 넣으면 오늘 |
| `AUTO_INCREMENT` | 번호 자동 증가 (MySQL) | 번호를 직접 관리하는 수고 |
| `CHECK (조건)` | 조건에 맞는 값만 허용 | 별점 6점, 음수 가격 |

> [!NOTE]
> 엑셀은 아무 칸에나 아무 값이나 넣을 수 있어서 결산할 때 데이터 검증에 시간이 많이 듭니다. DB는 **입력하는 순간** 제약조건으로 막기 때문에 데이터 품질이 지켜집니다. 정보처리기사의 **무결성**(개체 무결성 = PK, 참조 무결성 = FK)이 이 내용입니다.

## 4. 예제: 리뷰 테이블 만들기

카페에 "고객이 메뉴에 남긴 리뷰"를 저장한다고 해 봅시다.

```sql
USE cafe;

CREATE TABLE reviews (
    review_id    INT          PRIMARY KEY AUTO_INCREMENT,       -- 번호 자동 증가
    customer_id  INT          NOT NULL,                         -- 누가
    menu_id      INT          NOT NULL,                         -- 어떤 메뉴에
    rating       INT          NOT NULL CHECK (rating BETWEEN 1 AND 5),  -- 별점 1~5
    content      VARCHAR(200),                                  -- 내용 (없어도 됨)
    created_at   DATE         NOT NULL DEFAULT (CURRENT_DATE),  -- 안 넣으면 오늘
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id),
    FOREIGN KEY (menu_id)     REFERENCES menu(menu_id)
);
```

### 데이터 넣기: review_id와 created_at은 생략 가능

```sql
INSERT INTO reviews (customer_id, menu_id, rating, content)
VALUES (1, 2, 5, '아아 맛있어요'),
       (2, 3, 4, NULL);

SELECT * FROM reviews;   -- review_id 1, 2 자동 / created_at 오늘 날짜
```

### 구조 바꾸기: ALTER TABLE

```sql
ALTER TABLE reviews ADD COLUMN is_public TINYINT(1) NOT NULL DEFAULT 1;  -- 컬럼 추가
ALTER TABLE reviews DROP COLUMN is_public;                               -- 컬럼 삭제
```

### 테이블 지우기: DROP TABLE

```sql
DROP TABLE reviews;   -- 테이블 구조와 데이터가 통째로 사라짐 (되돌릴 수 없음)
```

| 명령 | 지우는 것 |
|---|---|
| `DELETE FROM t WHERE …` | **행** (9강) |
| `DROP TABLE t` | **테이블 자체** |

> [!WARNING]
> `DROP`은 트랜잭션으로도 되돌릴 수 없습니다. 실습 DB는 `cafe_schema.sql`로 복구되지만, 실무에서는 가장 조심해야 하는 명령입니다.

## 5. 정리: SQL 명령의 4가지 분류 (정보처리기사 단골)

| 분류 | 뜻 | 명령 | 배운 강 |
|---|---|---|---|
| **DDL** (정의어) | 구조를 만들고 바꿈 | CREATE, ALTER, DROP | 10강 |
| **DML** (조작어) | 데이터를 다룸 | SELECT, INSERT, UPDATE, DELETE | 1~9강 |
| **DCL** (제어어) | 권한 | GRANT, REVOKE | (2단계 이후) |
| **TCL** (트랜잭션 제어) | 확정·취소 | COMMIT, ROLLBACK | 9강 |
