# 8강: JOIN 입문 (INNER JOIN, LEFT JOIN)

## 오늘의 목표

- 테이블을 왜 나눠서 저장하는지 설명할 수 있다.
- `INNER JOIN`과 `LEFT JOIN`으로 두 테이블을 합칠 수 있다.
- 테이블 별칭(`o`, `c`)과 `테이블.컬럼` 표기를 쓸 수 있다.
- JOIN과 GROUP BY를 합쳐서 "메뉴 이름별 판매량" 같은 분석을 할 수 있다.

## 1. 왜 테이블을 나눠 둘까?

`orders` 테이블에는 고객 **이름**이 없고 `customer_id`(번호)만 있습니다.

만약 주문마다 고객 이름, 연락처, 지역을 다 적으면?
- 김민수가 3번 주문하면 같은 정보를 3번 적어야 합니다.
- 김민수가 연락처를 바꾸면 3군데를 다 고쳐야 하고, 하나라도 빠뜨리면 데이터가 서로 안 맞게 됩니다.

그래서 **고객 정보는 `customers`에 한 번만**, 주문에는 **고객 번호만** 적어 둡니다. 필요할 때 번호로 연결해서 합치는 것이 **JOIN**입니다.

> [!TIP]
> 엑셀의 **VLOOKUP / XLOOKUP**과 같습니다. "주문 시트의 고객번호로 고객 시트에서 이름을 찾아와라." 결산 업무에서 코드표로 이름을 붙이던 작업이 바로 이것입니다.

이렇게 다른 테이블을 가리키는 번호(`orders.customer_id` → `customers.customer_id`)를 **외래키(FK)**라고 합니다. 10강에서 자세히 다룹니다.

## 2. INNER JOIN: 양쪽에 다 있는 것만

```sql
SELECT o.order_id,
       o.order_date,
       c.name
FROM orders o
INNER JOIN customers c
        ON o.customer_id = c.customer_id;
```

- `orders o`: orders 테이블을 줄여서 `o`라고 부르겠다는 뜻입니다(**테이블 별칭**). `AS`는 생략합니다.
- `ON o.customer_id = c.customer_id`: **무엇으로 연결할지**를 정합니다. "주문의 고객번호와 고객의 고객번호가 같은 것끼리 붙여라."
- `o.order_id`: "o 테이블의 order_id". 두 테이블에 같은 이름의 컬럼이 있을 수 있어서 **어느 테이블 것인지** 붙여 씁니다.
- `INNER`는 생략 가능해서 그냥 `JOIN`이라고 써도 같습니다.

**결과: 16행.** 주문은 18건인데, 비회원 주문 2건은 `customer_id`가 NULL이라 `customers`에서 짝을 못 찾아서 **빠집니다.** INNER JOIN은 **양쪽 모두에 짝이 있는 행만** 남깁니다.

## 3. LEFT JOIN: 왼쪽은 전부 살린다

```sql
SELECT o.order_id,
       o.order_date,
       c.name
FROM orders o
LEFT JOIN customers c
       ON o.customer_id = c.customer_id;
```

**결과: 18행.** `FROM` 쪽(왼쪽) 테이블인 `orders`의 행은 **짝이 없어도 전부** 남기고, 짝이 없는 칸은 **NULL**로 채웁니다. 비회원 주문 2건은 `name`이 NULL로 나옵니다.

| 종류 | 남는 행 | 짝 없는 칸 | 언제 쓰나 |
|---|---|---|---|
| `INNER JOIN` | 양쪽 다 짝이 있는 행 | (빠짐) | 확실히 연결된 데이터만 볼 때 |
| `LEFT JOIN` | **왼쪽 전부** + 오른쪽 짝 | NULL | 왼쪽 데이터를 하나도 잃으면 안 될 때 |

> [!WARNING]
> 실무에서 "주문이 18건인데 보고서에는 16건으로 나와요"는 대부분 **LEFT JOIN을 써야 할 자리에 INNER JOIN을 써서** 생깁니다. JOIN 후에는 꼭 **행 수가 맞는지** 확인하세요.

### LEFT JOIN으로 "없는 것" 찾기

```sql
-- 한 번도 주문하지 않은 고객
SELECT c.name
FROM customers c
LEFT JOIN orders o
       ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;
```

고객을 전부 살린 뒤, 주문 쪽이 NULL인 사람 = **주문 기록이 없는 사람**입니다. "가입만 하고 구매 안 한 고객", "판매 안 된 상품" 찾기에 자주 쓰는 패턴입니다.

## 4. 테이블 3개 이상 합치기

`order_items`에는 메뉴 **번호**만 있습니다. 메뉴 이름을 보려면 `menu`와 합칩니다.

```sql
SELECT c.name      AS 고객이름,
       o.order_date AS 주문일,
       m.name      AS 메뉴이름,
       oi.quantity AS 수량
FROM orders o
JOIN customers   c  ON o.customer_id = c.customer_id
JOIN order_items oi ON o.order_id    = oi.order_id
JOIN menu        m  ON oi.menu_id    = m.menu_id;
```

JOIN을 한 줄씩 이어 붙이면 됩니다. 각 JOIN마다 `ON`으로 연결 기준을 적습니다.

> [!NOTE]
> `customers`와 `menu`에 둘 다 `name` 컬럼이 있습니다. 그냥 `name`이라고 쓰면 MySQL은 어느 쪽인지 몰라서 오류를 냅니다. 그래서 `c.name`, `m.name`처럼 **테이블 별칭을 붙이는 습관**이 중요합니다.

## 5. JOIN + GROUP BY: 진짜 분석의 시작

7강 6번에서 메뉴 **번호**별 판매량만 볼 수 있었던 걸, 이제 **이름**으로 볼 수 있습니다.

```sql
SELECT m.name           AS 메뉴이름,
       SUM(oi.quantity) AS 판매수량
FROM order_items oi
JOIN menu m ON oi.menu_id = m.menu_id
GROUP BY m.menu_id, m.name
ORDER BY 판매수량 DESC;
```

- 실행 순서: **FROM + JOIN**(합치기) → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. JOIN은 FROM 단계에서 합쳐진다고 보면 됩니다.
- `GROUP BY m.menu_id, m.name`: 이름이 같은 다른 메뉴가 있을 수 있으니 **번호(고유값)로 묶고** 이름은 보여 주기용으로 같이 둡니다. 실무에서 쓰는 안전한 방식입니다.

## 6. 실무에서는 이렇게 쓰입니다

- 실무 DB는 테이블이 수십~수백 개입니다. JOIN 없는 분석 쿼리는 거의 없습니다.
- "상품명별 매출", "고객 등급별 구매액", "지점별 직원 실적" 모두 JOIN + GROUP BY입니다.
- 면접 단골 질문: "INNER JOIN과 LEFT JOIN의 차이는?", "주문 없는 고객은 어떻게 찾나요?"

### 피드백 1: 6번, "횟수"는 SUM이 아니라 COUNT

```sql
sum(o.customer_id) as 주문횟수   -- ❌ 고객번호를 더함
```

`SUM(o.customer_id)`는 **고객번호 숫자를 더한 값**입니다.

| 고객 | 고객번호 | 주문 | SUM(customer_id) | 실제 주문횟수 COUNT(*) |
|---|---|---|---|---|
| 김민수 | 1 | 3건 | 1+1+1 = **3** | 3 |
| 이서연 | 2 | 3건 | 2+2+2 = **6** | 3 |
| 윤채원 | 7 | 2건 | 7+7 = **14** | 2 |

김민수는 고객번호가 1이라 **우연히** 3이 나와서 첫 행이 힌트와 같아 보였습니다. 다른 행을 보면 윤채원 14회처럼 말이 안 되는 숫자가 나옵니다. **첫 행만 보지 말고 결과 전체가 상식적인지**도 확인하세요.

```sql
SELECT c.name   AS 고객이름,
       COUNT(*) AS 주문횟수
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.name
ORDER BY 주문횟수 DESC, 고객이름;
```

- 개수(횟수, 건수, 명수) → `COUNT`, 합계(금액, 수량) → `SUM`
- 정렬도 `ORDER BY 주문횟수`(오름차순)만 있어서 "많은 순, 같으면 이름 순"이 빠졌습니다.

### 피드백 2: 4번, 동점일 때 기준이 빠짐

3위가 **아메리카노 4개, 치즈케이크 4개로 동점**입니다. `ORDER BY 판매수량 DESC`만 있으면 둘 중 어느 쪽이 3위로 나올지 보장되지 않습니다. 문제의 "같으면 메뉴 이름 순"을 넣어야 합니다.

```sql
ORDER BY 판매수량 DESC, 메뉴이름
LIMIT 3;
```

4강 3번에서 맞혔던 내용입니다. LIMIT으로 자를 때 경계에 동점이 있으면 결과가 실행할 때마다 달라질 수 있습니다.
