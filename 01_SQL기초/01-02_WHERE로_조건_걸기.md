# 2강: WHERE로 조건 걸기

## 오늘의 목표

- `WHERE`로 원하는 **행**만 골라낼 수 있다.
- 비교 연산자(`=`, `<>`, `>`, `>=` …)와 `AND` / `OR` / `NOT`을 쓸 수 있다.
- `BETWEEN`, `IN`, `LIKE`로 조건을 짧게 쓸 수 있다.

> [!NOTE]
> 1강의 `SELECT`가 **열(세로)**을 고르는 것이라면, 오늘 배우는 `WHERE`는 **행(가로)**을 고르는 것입니다. 엑셀로 치면 **자동 필터**입니다.

## 1. 기본 문장

```sql
SELECT 보여줄_컬럼
FROM   테이블
WHERE  조건;
```

DB는 테이블의 행을 하나씩 보면서 조건이 **참**인 행만 남깁니다.

### 예제 1: 같다 (`=`)

```sql
SELECT name, price
FROM menu
WHERE category = '디저트';
```

- 글자 값은 **작은따옴표** `'디저트'`로 감쌉니다. (1강 피드백에서 별칭에는 쓰지 말자고 한 이유가 이것입니다)
- 숫자는 따옴표 없이 씁니다: `WHERE price = 4000`

## 2. 비교 연산자

| 연산자 | 뜻 | 예시 |
|---|---|---|
| `=` | 같다 | `city = '서울'` |
| `<>` 또는 `!=` | 같지 않다 | `city <> '서울'` |
| `>` / `<` | 크다 / 작다 | `price > 5000` |
| `>=` / `<=` | 이상 / 이하 | `price >= 5000` |

### 예제 2: 서울에 살지 않는 고객

```sql
SELECT name, city
FROM customers
WHERE city <> '서울';
```

결과 5행. `<>`가 표준 SQL이고, `!=`도 MySQL·Oracle에서 모두 됩니다.

### 예제 3: 날짜 비교

```sql
SELECT order_id, order_date
FROM orders
WHERE order_date >= '2025-10-08';
```

날짜도 `'YYYY-MM-DD'` 형태로 따옴표에 넣어 비교합니다.

## 3. 조건 여러 개: AND, OR, NOT

| 연산자 | 뜻 |
|---|---|
| `A AND B` | A와 B **둘 다** 참 |
| `A OR B` | A나 B 중 **하나라도** 참 |
| `NOT A` | A가 아닌 것 |

### 예제 4: 커피 중에서 아이스인 메뉴

```sql
SELECT name, price
FROM menu
WHERE category = '커피'
  AND is_iced = 1;
```

### 예제 5: 서울이나 부산에 사는 고객

```sql
SELECT name, city
FROM customers
WHERE city = '서울'
   OR city = '부산';
```

> [!WARNING]
> **AND가 OR보다 먼저 계산됩니다.** 곱셈이 덧셈보다 먼저인 것과 같습니다. AND와 OR를 섞을 때는 **괄호 `( )`**로 묶으세요. 실무에서 가장 흔한 실수이고, 오류 없이 **틀린 결과**가 나와서 더 위험합니다. 실습 문제 8번에서 직접 확인해 봅니다.

## 4. 짧게 쓰는 조건: BETWEEN, IN, LIKE

### BETWEEN: 범위

```sql
SELECT name, price
FROM menu
WHERE price BETWEEN 4000 AND 5000;   -- 4000 이상 5000 이하 (양 끝 포함)
```

`price >= 4000 AND price <= 5000`과 같습니다.

### IN: 목록 중 하나

```sql
SELECT order_id, payment
FROM orders
WHERE payment IN ('현금', '페이');
```

`payment = '현금' OR payment = '페이'`와 같습니다. 값이 많을수록 IN이 훨씬 깔끔합니다. 반대는 `NOT IN`.

### LIKE: 글자 패턴

| 기호 | 뜻 | 예시 | 찾는 것 |
|---|---|---|---|
| `%` | 아무 글자 0개 이상 | `'아이스%'` | 아이스로 **시작** |
| | | `'%라떼'` | 라떼로 **끝남** |
| | | `'%초코%'` | 초코가 **들어 있음** |
| `_` | 아무 글자 딱 1개 | `'김__'` | 김으로 시작하는 세 글자 |

```sql
SELECT name, phone
FROM customers
WHERE name LIKE '김%';
```

## 5. 실무에서는 이렇게 쓰입니다

- "10월 첫째 주 카드 결제 건만 뽑아 주세요" → 날짜 `BETWEEN` + `payment = '카드'`
- "서울·경기 고객만 문자 보낼게요" → `city IN ('서울', '경기')`
- "상품명에 '세트'가 들어간 것만" → `LIKE '%세트%'`

실무 데이터는 수십만~수백만 행이라 `WHERE` 없이 조회하는 일은 거의 없습니다. 쿼리를 쓸 때 "**어떤 열**을(SELECT) **어디서**(FROM) **어떤 행만**(WHERE)" 순서로 생각하는 습관을 들이세요.

## 실습 문제

답안 칸에는 `-- ` 없이 **쿼리만** 적어 주세요. 각 문제 옆의 **(결과 N행)**과 내 결과의 행 수가 같은지 직접 확인해 보세요. 다 풀면 채팅에 **"2강 답안 제출"**.

**문제 1.** 가격이 5000원 이상인 메뉴의 이름과 가격을 조회하세요. (결과 8행)

```sql
select name as 메뉴이름, price as 가격 from menu where price >= 5000;
```

**문제 2.** 서울에 사는 고객의 이름과 출생연도를 조회하세요. (결과 5행)

```sql
select name as 고객이름, birth_year as 출생년도, city as 사는지역 from customers where city in ('서울');
```

**문제 3.** 디저트이면서 가격이 6000원 미만인 메뉴의 이름과 가격을 조회하세요. (결과 2행)

```sql
select name as 메뉴이름, price as 가격, category as 분류 from menu where category = '디저트' and price < 6000;
```

**문제 4.** 경기 또는 인천에 사는 고객의 이름과 지역을 조회하세요. **`IN`을 사용하세요.** (결과 4행)

```sql
select name as 고객이름, city as 사는지역 from customers where city in ('경기', '인천');
```

**문제 5.** 가격이 4500원 이상 5500원 이하인 메뉴의 이름과 가격을 조회하세요. **`BETWEEN`을 사용하세요.** (결과 8행)

```sql
select name as 메뉴이름, price as 가격 from menu where price between 4500 and 5500;
```

**문제 6.** 이름에 '라떼'가 들어가는 메뉴의 이름을 조회하세요. (결과 4행)

```sql
select name as 메뉴이름 from menu where name like '%라떼';
```

**문제 7.** 2025년 10월 5일부터 10월 8일까지(양 끝 포함) 주문 중 **카드**로 결제한 주문의 주문번호와 주문일을 조회하세요. (결과 3행)

```sql
select order_id as 주문번호, order_date as 주문일 from orders where order_date between '2025-10-05' and '2025-10-08' and payment = '카드';
```

**문제 8. (함정 문제)** "커피나 논커피 중에서 가격이 5000원 이상인 메뉴"의 이름, 분류, 가격을 조회하세요. (결과 5행)
→ 먼저 괄호 **없이** 써서 실행해 보고, 몇 행이 나오는지, 왜 그런지 적어 주세요. 그다음 올바른 쿼리를 쓰세요.

```sql
-- 괄호 없이 쓴 쿼리 (결과 __행)
select name as 이름, category as 분류, price as 가격 from menu where category = '커피' or category = '논커피' and price >= 5000;

-- 올바른 쿼리
select name as 이름, category as 분류, price as 가격 from menu where category in ('커피', '논커피') and price >= 5000;
```

왜 결과가 달랐나요?
>가격이 5000원 이상이라는 조건이 괄호 없이 쓴 쿼리에는 적용이 안되어서 이름이 '커피', '논커피'인 데이터가 다 나오고, IN ()를 사용할 경우 가격이 5000원 이상이라는 조건이 적용 되어 잘 나옴. 내 생각으로는 or절 and절이 같이 적용이 안되는 것 같음.

### 피드백 1: `'%라떼'` vs `'%라떼%'`

- `'%라떼'` = 라떼로 **끝나는** 것
- `'%라떼%'` = 라떼가 **어디든 들어 있는** 것 ← 문제가 요구한 것

지금 데이터에서는 라떼 메뉴가 전부 "~라떼"로 끝나서 우연히 4행이 맞았습니다. 하지만 메뉴에 `라떼쿠키`가 추가되면 놓칩니다. **결과가 맞아도 조건이 문제의 뜻과 같은지** 확인하는 습관이 중요합니다. 실무에서는 데이터가 계속 바뀌기 때문입니다.

### 피드백 2: AND가 OR보다 먼저 계산된다

"OR와 AND가 같이 적용이 안 된다"가 아니라, **AND가 먼저 묶인다**가 정확한 원인입니다. 괄호 없이 쓴 쿼리를 DB는 이렇게 읽습니다.

```sql
WHERE category = '커피'
   OR (category = '논커피' AND price >= 5000)
```

- 커피는 가격 조건 없이 **전부** (5행)
- 논커피는 5000원 이상만 (3행)
- 합계 **8행**. 그래서 4000원짜리 아메리카노가 섞여 나왔습니다.

올바른 쿼리는 IN으로 쓴 풀이 외에 괄호로도 쓸 수 있습니다.

```sql
SELECT name, category, price
FROM menu
WHERE (category = '커피' OR category = '논커피')
  AND price >= 5000;
```

### 피드백 3: SELECT는 열, WHERE는 행

이번에도 반대로 답했습니다. 쿼리는 다 맞게 쓰셨으니 개념은 이해하고 계신데 **이름표만 바뀌어 있는** 상태입니다. 외우는 법:

- **열 = column(컬럼) = 기둥** → 기둥은 **세로**로 서 있다 → `name`, `price` 같은 항목
- **행 = row(로우) = 줄** → 줄을 서면 **가로**로 이어진다 → "치즈케이크 | 디저트 | 6000" 같은 데이터 한 건
- DBeaver 결과 창 맨 위 머리글(`name`, `price`)이 **컬럼**, 그 아래 한 줄 한 줄이 **행**입니다. 결과 창 하단의 "8 row(s) fetched"도 "8**행**을 가져왔다"는 뜻입니다.
- 따라서 `SELECT name, price` → **열**(기둥)을 고른다 / `WHERE price >= 5000` → 조건에 맞는 **행**(줄)을 고른다
