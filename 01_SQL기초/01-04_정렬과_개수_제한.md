# 4강: 정렬과 개수 제한 (ORDER BY, LIMIT, DISTINCT)

## 0. 복습: 따옴표가 있으면 글자, 없으면 컬럼

1강부터 3강까지 같은 실수가 반복되어서, 4강을 시작하기 전에 한 번 더 정리합니다.

| 쓴 것 | SQL이 읽는 뜻 | 결과 |
|---|---|---|
| `city` | **컬럼** city에 들어 있는 값 | 서울, 경기, … (행마다 다름) |
| `'city'` | **글자** c-i-t-y | 모든 행에 `city`라는 글자 |
| `'서울'` | **글자** 서울 | WHERE 비교용 값 |
| `서울` | **컬럼** 서울 (그런 컬럼 없음) | 오류 `Unknown column '서울'` |

직접 실행해서 눈으로 확인해 보세요.

```sql
SELECT name,
       city,          -- 컬럼: 사람마다 다른 지역
       'city',        -- 글자: 모두 'city'
       '고객' AS 구분  -- 글자: 모두 '고객'
FROM customers;
```

> [!TIP]
> 외우는 법: **작은따옴표는 "내가 직접 타이핑한 값"**입니다. 테이블에서 꺼내 와야 하는 값이면 따옴표를 쓰지 않습니다.

## 오늘의 목표

- `ORDER BY`로 결과를 원하는 순서로 정렬할 수 있다.
- `LIMIT`으로 위에서부터 N개만 가져올 수 있다. (TOP 3, 최근 5건 같은 질문)
- `DISTINCT`로 중복을 없앨 수 있다.

## 1. ORDER BY: 정렬

```sql
SELECT name, price
FROM menu
ORDER BY price;          -- 오름차순 (작은 것 → 큰 것), ASC 생략 가능
```

```sql
SELECT name, price
FROM menu
ORDER BY price DESC;     -- 내림차순 (큰 것 → 작은 것)
```

| 키워드 | 뜻 | 숫자 | 글자 | 날짜 |
|---|---|---|---|---|
| `ASC` (기본값) | 오름차순 | 1 → 9 | ㄱ → ㅎ, A → Z | 옛날 → 최근 |
| `DESC` | 내림차순 | 9 → 1 | ㅎ → ㄱ | 최근 → 옛날 |

### 여러 기준으로 정렬

```sql
SELECT name, category, price
FROM menu
ORDER BY category ASC, price DESC;
```

**먼저 category로 정렬**하고, category가 같은 행끼리는 **price가 큰 순서**로 정렬합니다. 엑셀의 "정렬 기준 추가"와 같습니다. 정렬 방향(ASC/DESC)은 **기준마다 따로** 붙입니다.

### 별칭으로 정렬하기

```sql
SELECT name, price * 2 AS 두개가격
FROM menu
ORDER BY 두개가격 DESC;
```

ORDER BY는 SELECT보다 나중에 실행되기 때문에 SELECT에서 만든 별칭을 쓸 수 있습니다. (WHERE에서는 별칭을 못 씁니다. 실행 순서는 아래에서 설명)

## 2. LIMIT: 위에서 N개만

```sql
SELECT name, price
FROM menu
WHERE category = '디저트'
ORDER BY price DESC
LIMIT 2;                 -- 디저트 중 가장 비싼 2개: 티라미수, 치즈케이크
```

- `LIMIT`은 **반드시 ORDER BY와 함께** 써야 의미가 있습니다. 정렬 없이 LIMIT을 쓰면 DB 마음대로 아무 행이나 N개를 줍니다.
- **동점 주의:** 가격이 같은 메뉴가 경계에 걸리면 어떤 게 나올지 보장되지 않습니다. 이럴 때는 `ORDER BY price DESC, name`처럼 **두 번째 기준**을 넣어서 순서를 확정합니다.

> [!NOTE]
> `LIMIT`은 MySQL·PostgreSQL·SQLite 문법입니다. Oracle은 `FETCH FIRST 2 ROWS ONLY`, SQL Server는 `SELECT TOP 2`를 씁니다. 뜻은 같습니다.

## 3. DISTINCT: 중복 없애기

```sql
SELECT DISTINCT category
FROM menu;               -- 커피, 논커피, 디저트 (3행)
```

12개 메뉴의 분류에서 중복을 빼고 **종류만** 보여 줍니다. 엑셀의 "중복된 항목 제거"와 같습니다.

```sql
SELECT DISTINCT category, is_iced
FROM menu;
```

열을 여러 개 쓰면 **조합**이 같은 행만 중복으로 봅니다. (커피+아이스, 커피+핫, … 각각 1행)

## 4. 쿼리 실행 순서 (중요)

쓰는 순서와 DB가 실행하는 순서가 다릅니다.

| 쓰는 순서 | 실행 순서 | 하는 일 |
|---|---|---|
| 1. SELECT | 3 | 보여 줄 열을 고르고 별칭을 붙인다 |
| 2. FROM | **1** | 테이블을 가져온다 |
| 3. WHERE | **2** | 조건에 맞는 행만 남긴다 |
| 4. ORDER BY | 4 | 정렬한다 |
| 5. LIMIT | 5 | 위에서 N개만 자른다 |

그래서 SELECT에서 만든 별칭을 **ORDER BY에서는 쓸 수 있고, WHERE에서는 못 씁니다.** WHERE가 실행될 때는 아직 별칭이 만들어지지 않았기 때문입니다. 5강 이후에 GROUP BY, HAVING이 이 표에 추가됩니다.

## 5. 실무에서는 이렇게 쓰입니다

- "이번 달 매출 TOP 10 상품" → `ORDER BY 매출 DESC LIMIT 10`
- "최근 가입자 5명" → `ORDER BY join_date DESC LIMIT 5`
- "우리 고객은 어느 지역에 있나요?" → `SELECT DISTINCT city`
- 보고서는 거의 항상 정렬해서 냅니다. 정렬 안 된 표는 읽는 사람이 다시 정렬해야 합니다.
