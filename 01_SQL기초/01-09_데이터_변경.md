# 9강: 데이터 변경 (INSERT, UPDATE, DELETE, 트랜잭션)

## 오늘의 목표

- `INSERT`로 행을 추가하고, `UPDATE`로 값을 바꾸고, `DELETE`로 행을 지울 수 있다.
- **WHERE 없는 UPDATE/DELETE가 왜 위험한지** 설명할 수 있다.
- `START TRANSACTION` / `ROLLBACK` / `COMMIT`으로 실수를 되돌릴 수 있다.

> [!WARNING]
> 1~8강의 SELECT는 데이터를 **읽기만** 했습니다. 오늘 배우는 문장은 데이터를 **실제로 바꿉니다.** 실습 DB는 언제든 `db/cafe_schema.sql`을 `Alt + X`로 다시 실행하면 처음 상태로 돌아가니 마음 놓고 연습하세요. 실무에서는 운영 DB에 함부로 쓰면 안 됩니다.

## 1. INSERT: 행 추가

```sql
INSERT INTO menu (menu_id, name, category, price, is_iced)
VALUES (13, '레몬에이드', '논커피', 5500, 1);
```

- `INSERT INTO 테이블 (컬럼들) VALUES (값들)`: 컬럼과 값을 **같은 순서**로 짝지어 씁니다.
- 실행하면 DBeaver 결과 창에 `Updated Rows: 1`처럼 **바뀐 행 수**가 나옵니다. SELECT처럼 표가 나오지 않습니다.
- 바뀌었는지는 SELECT로 직접 확인합니다: `SELECT * FROM menu WHERE menu_id = 13;`

### 여러 행 한 번에, 일부 컬럼만

```sql
INSERT INTO customers (customer_id, name, gender, birth_year, city, join_date)
VALUES (11, '신지아', 'F', 1998, '서울', '2025-10-20'),
       (12, '배현우', 'M', 1994, '대전', '2025-10-25');
```

- 값 묶음을 쉼표로 이어 쓰면 여러 행이 한 번에 들어갑니다.
- 적지 않은 컬럼(`phone`)은 **NULL**이 됩니다.
- 컬럼 목록을 생략하고 `VALUES (...)`만 쓸 수도 있지만(`cafe_schema.sql`이 그렇게 되어 있습니다), 테이블 구조가 바뀌면 깨지기 때문에 **실무에서는 컬럼 목록을 꼭 적습니다.**

## 2. UPDATE: 값 바꾸기

```sql
UPDATE menu
SET price = 4300
WHERE menu_id = 1;
```

- `SET 컬럼 = 새값`: 여러 개면 `SET price = 4300, is_iced = 0`처럼 쉼표로 잇습니다.
- `WHERE`에 걸린 행만 바뀝니다.

### 계산으로 바꾸기

```sql
UPDATE menu
SET price = price + 500         -- 지금 가격에 500을 더한 값으로
WHERE category = '디저트';       -- 4행이 바뀜
```

## 3. DELETE: 행 지우기

```sql
DELETE FROM menu
WHERE menu_id = 13;
```

행 전체가 지워집니다. 특정 칸만 비우고 싶다면 DELETE가 아니라 `UPDATE ... SET phone = NULL`입니다.

## 4. 가장 위험한 실수: WHERE를 빠뜨리기

```sql
UPDATE menu SET price = 0;     -- 😱 메뉴 12개 가격이 전부 0원
DELETE FROM customers;          -- 😱 고객 전부 삭제 시도
```

오류가 나지 않습니다. **조용히 전체 행이 바뀝니다.** 실무에서 실제로 일어나는 대형 사고입니다.

### 안전 습관 3가지

1. **SELECT로 먼저 확인**: 바꾸기 전에 같은 WHERE로 SELECT를 실행해서 **몇 행이, 어떤 행이** 걸리는지 봅니다.
   ```sql
   SELECT * FROM menu WHERE category = '디저트';   -- 4행 확인 후
   UPDATE menu SET price = price + 500 WHERE category = '디저트';
   ```
2. **WHERE부터 쓰기**: `UPDATE menu` 다음에 `WHERE`를 먼저 적고 SET을 채웁니다.
3. **트랜잭션 안에서 실행**: 아래 5번.

> [!NOTE]
> DBeaver는 WHERE 없는 UPDATE/DELETE를 실행하려고 하면 확인 창을 띄울 수 있습니다. 확인 창이 나오면 **그냥 넘기지 말고** 정말 전체를 바꾸려는 건지 다시 보세요.

## 5. 트랜잭션: 되돌릴 수 있는 작업 단위

DBeaver는 기본적으로 **자동 커밋(Auto-commit)**이라, 실행하는 순간 바로 저장됩니다. `START TRANSACTION`으로 시작하면 `COMMIT`이나 `ROLLBACK`을 할 때까지 **확정이 미뤄집니다.**

```sql
START TRANSACTION;                 -- ① 여기부터 임시 작업

UPDATE menu SET price = 0;         -- ② 실수! WHERE 없음

SELECT name, price FROM menu;      -- ③ 전부 0원인 걸 확인

ROLLBACK;                          -- ④ START TRANSACTION 이후 작업 전부 취소

SELECT name, price FROM menu;      -- ⑤ 원래 가격으로 돌아옴
```

| 명령 | 뜻 | 비유 |
|---|---|---|
| `START TRANSACTION` | 작업 시작 | 문서 편집 시작 |
| `COMMIT` | 확정 저장 | Ctrl + S |
| `ROLLBACK` | 전부 취소 | 저장 안 하고 닫기 |

> [!TIP]
> 은행 이체가 대표적인 트랜잭션 예입니다. "A 계좌에서 빼기"와 "B 계좌에 넣기"는 **둘 다 되거나, 둘 다 안 되어야** 합니다. 하나만 되면 돈이 사라지니까요. 정보처리기사에서 나오는 트랜잭션의 **원자성(Atomicity)**이 이 뜻입니다.

## 6. 지워지지 않는 경우: 외래키(FK)

```sql
DELETE FROM customers WHERE customer_id = 8;   -- 임준호
```

`SQL Error [1451]: Cannot delete or update a parent row: a foreign key constraint fails`

임준호는 `orders`에 주문 기록이 있습니다. 고객을 지우면 그 주문이 **존재하지 않는 고객**을 가리키게 되니까, DB가 삭제를 막습니다. 이것이 8강에서 말한 **외래키(FK)**의 역할입니다. 10강에서 직접 만들어 봅니다.

## 7. 실무에서는 이렇게 쓰입니다

- 데이터 분석가는 주로 **SELECT만** 씁니다. 운영 DB에는 쓰기 권한이 없는 경우가 대부분입니다.
- 그래도 알아야 하는 이유: 분석용 임시 테이블을 만들어 정리하거나, 데이터 오류를 고쳐 달라고 요청할 때 "어떤 행을, 어떻게 바꿔야 하는지" 정확히 말할 수 있어야 합니다.
- "UPDATE 하기 전에 SELECT로 확인", "트랜잭션으로 감싸기"는 면접에서 **실무 감각**을 보여 주는 답변입니다.
